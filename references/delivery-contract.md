# 交付与复核规范

本文件规定本 skill 的成果组织方式。它属于工作流程说明，不是 GB/T 1.1—2020 的标准条款。

## 1. 两份主成果

| 文件 | 内容 | 默认形式 |
| --- | --- | --- |
| `原文件名_审查说明及修改建议.docx` | 审查说明、逐项问题与修改建议、覆盖情况、待确认事项、文件检查结果 | 可编辑 Word |
| `原文件名_修订稿.docx` | 已落实确定性修改的完整标准文件 | 保留原稿结构和必要对象的可编辑 Word |

日期和版本可加在文件名中，避免覆盖已有成果。用户指定格式时按指定格式交付。用户只要求审查时不生成擅自修改的标准文件。内部清点 JSON、进度记录、渲染 PDF 等放在工作目录，需要追溯时提供，不增加默认交付负担。

## 2. 审查说明及修改建议

### 2.1 审查说明

简要写明：

- 审查对象：文件名、版本或稿件日期、稿件阶段，原文件哈希或其他可复核标识。
- 使用依据：实际取得的标准名称及版本、手册、模板、项目要求；skill 的可获得版本标识。
- 处理范围：全文或用户限定的范围；结构审查、逐章修订和专项复核的实际完成情况。
- 主要发现和修改概况，优先写影响范围、条款类型和执行理解的问题。

信息未知即记录未知，不补写官方标准号、立项编号、机构、日期、审核人员或审批结论。

### 2.2 问题与建议记录

每项问题有唯一编号，至少包含：

| 字段 | 要求 |
| --- | --- |
| 问题编号与类别 | 如 R001；A 结构及规则问题 / B 技术表达风险 / C 编辑格式问题。这是本工具的工作分类，不是标准规定的等级。 |
| 位置 | 原稿章条、表/图/公式/附录编号、单元格或可定位原句；迁移后补充新位置。仅页码不足以稳定定位。 |
| 原文与问题 | 保留足够上下文，说明具体问题及其影响。 |
| 修改后文本或建议 | 能改文字时给完整可替换段落；表格给具体单元格改文，结构调整给完整动作；不使用“略”“同上”代替。 |
| 依据 | 使用下述依据类型，并写明可复核位置及判断理由。 |
| 处理状态 | 已修改 / 待确认而保留原文 / 仅建议未实施；说明原因。 |

依据分三类：

1. **标准原文已核对**：写标准编号、版本及实际核对的条号，必要时引用短句。只有手册提及的条号，不属于已核对原文。
2. **手册检查点**：写“审查工作手册 §7 条款类型和能愿动词”等可复核标题；不能把手册章节号写成 GB/T 1.1 条号。
3. **编辑建议**：说明是清晰性、一致性或版式优化建议，不将偏好定性为标准强制要求。

手册中的示例条号不应直接套用。标准原文、模板或项目要求发生冲突时写明冲突双方及待核内容。已有依据足以确定的修改先完成。

### 2.3 待确认事项

仅列需要起草人作出决定的具体事项，例如某一处应保持要求还是改为推荐、缺少何项技术判定依据、某引用版本应如何选择。每项写位置、原文保留方式、候选处理和所需信息。没有待确认事项就写“无”，不生成泛化风险清单。

## 3. 覆盖记录

先清点再审查。正文以最小可定位段落或条款为记录单位；表格记录到单元格或明确区域；图、公式、附录、脚注、文本框等单独定位。覆盖状态使用：

- 未审查：初始状态。
- 已审查—已修改：确定性修改已写入修订稿。
- 已审查—无需修改：已完成检查，原文保留。
- 已审查—待确认：已经分析，但需要技术选择或补充依据；未确认内容保留。
- 未完成—无法读取/核验：说明具体对象和原因，不能算入已审查数。

工作记录至少含 `对象ID / 原位置 / 对象类型 / 审查状态 / 问题编号 / 新位置（如变化）`。一个段落有多个问题时分别记录；对同一对象的嵌套清点避免重复统计，说明采用的统计口径。

报告按封面及前置要素、各章、附录、图表公式、文后内容汇总，并保留可追溯的对象记录或附表。缺失的必备要素作为问题记录，不能因原稿没有该要素而略过。报告中区分：

- **审查覆盖**：已经检查哪些对象，哪些未读取或未核验。
- **问题落实**：已实施多少修改，多少建议尚待确认。

覆盖全稿不意味着所有技术问题均已解决。只有清点和记录相符时才能报告覆盖完成，不能仅根据检索命中数声称“无遗漏”。

## 4. 文件保真与验收

1. **原稿保护**：记录输入哈希；副本编辑；结束后复核输入哈希未变。保留原稿历史修订和批注的处理说明。
2. **内容对照**：比较原稿与修订稿正文、表格、图片、公式、脚注、引用等。逐项解释删改或迁移；避免只比正文段落数量。
3. **技术要素对照**：检查数字、量值、单位、范围、条件、例外、否定及能愿动词变化。原文已冲突时保留争议并给出建议，不凭格式偏好裁定。
4. **记录一致性**：抽取并重读修订文件，逐项核对报告中的“已修改”；确定性修改不能只存在于聊天或报告中。
5. **结构复核**：核对编号、交叉引用、目录、附录性质及文献对应。更新可更新的域；不能更新的目录页码等说明具体位置。
6. **视觉检查**：实际渲染报告和修订稿，查看每页并修正溢出、截断、图表错位、分页异常。复杂表格、公式、文字绕图和附录重点检查。没有渲染器时如实记录所做的结构检查及尚未进行的视觉检查。
7. **交付检查**：两份文件存在、非空、能重新打开；文件名和正文版本一致；最终回复给出用户可访问路径。

验收结论基于实际检查，不将成功解压 DOCX、文本可提取或脚本通过等同于标准符合性审查通过。
